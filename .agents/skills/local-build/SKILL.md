# Local Build & Test on the Mac

LockerLift is built and tested locally on the Mac in Android Studio. Two emulators run alongside for installing and verifying APKs: a smartphone emulator and a Wear OS emulator. No remote build server is used anymore; the old Ubuntu server instructions are retired.

## Toolchain locations

| Component | Version | Path |
|---|---|---|
| JDK | JetBrains Runtime 21 (`JAVA_HOME`) | `~/Library/Java/JavaVirtualMachines/jbr-21.0.11/Contents/Home` (bundled with Android Studio) |
| Gradle | 9.6.0 (must match `gradle-wrapper.properties`; AGP 9.4.1 requires >= 9.6.0) | `~/.gradle/wrapper/dists/gradle-9.6.0-bin/<hash>/gradle-9.6.0` (populated by the first Android Studio Gradle sync) |
| Android SDK | platforms + build-tools 35 | `~/Library/Android/sdk` |
| ADB | platform-tools | `~/Library/Android/sdk/platform-tools` |

There is **no** `gradlew` wrapper script in the repo. Use the `gradle` binary from the wrapper dists directory, or build directly from Android Studio:

```sh
GRADLE_BIN=$(ls -d ~/.gradle/wrapper/dists/gradle-9.6.0-bin/*/gradle-9.6.0/bin/gradle | head -1)
JAVA_HOME=~/Library/Java/JavaVirtualMachines/jbr-21.0.11/Contents/Home
```

If the dist directory does not exist yet, either open the project once in Android Studio (its Gradle sync downloads it) or download it once:

```sh
curl -sL -o /tmp/gradle-9.6.0-bin.zip https://services.gradle.org/distributions/gradle-9.6.0-bin.zip
unzip -q -o /tmp/gradle-9.6.0-bin.zip -d /tmp
```

`local.properties` in the repo root points to the SDK: `sdk.dir=/Users/<user>/Library/Android/sdk`. Do not commit it.

`gradle/gradle-daemon-jvm.properties` is generated by Android Studio and pins the daemon toolchain to vendor `jetbrains`, version 21, so CLI and Android Studio builds use the same JDK. Keep it **untracked** (it is IDE-local): CI runners use Temurin 21 and cannot provision a JetBrains JDK, so committing it breaks every CI build with a toolchain download error.

## Gradle invocation

The Mac has enough RAM — no memory throttling flags are needed. The project's `gradle.properties` heap settings are fine as-is.

## Common commands

```sh
# Full unit-test suite across all modules (E2E sync suite is skipped by default, same as CI)
"$GRADLE_BIN" test

# Run the in-memory E2E sync test suite explicitly
"$GRADLE_BIN" test -PrunE2eSync=true

# Compile a single module fast (first sanity check after edits)
"$GRADLE_BIN" :wear:compileDebugKotlin

# Build debug APKs (output in mobile/build/outputs/apk/debug/ and wear/build/outputs/apk/debug/)
"$GRADLE_BIN" :mobile:assembleDebug :wear:assembleDebug

# Clean (when gradle state seems stuck)
"$GRADLE_BIN" clean
```

## Emulators

Two emulators are typically running (check with `adb devices -l`):

| Emulator | Image | Purpose |
|---|---|---|
| `emulator-5554` | `sdk_gwear_arm64` (Wear OS) | Install/test the `:wear` app: `adb -s emulator-5554 install -r wear/build/outputs/apk/debug/wear-debug.apk` |
| `emulator-5556` | `sdk_gphone16k_arm64` (phone) | Install/test the `:mobile` app: `adb -s emulator-5556 install -r mobile/build/outputs/apk/debug/mobile-debug.apk` |

For Wear OS specific procedures (waking the watch, keeping the display on, UI dumps, screenshots, logcat) see the `wear-os-adb-guide` skill.

## Troubleshooting

- `Minimum supported Gradle version is X` → the Gradle binary is older than the AGP in `gradle/libs.versions.toml` requires. Use the wrapper dist matching `gradle-wrapper.properties`.
- `sdk.dir is missing` / `local.properties` complains → verify `sdk.dir=/Users/<user>/Library/Android/sdk`.
- `error: unresolved reference 'bodyExtraSmall'` (or similar) → these slots exist only in Wear Compose Material 3; the wear screens are migrated to `androidx.wear.compose.material3`, so use the wear Material 3 typography/components there.
- `Gradle Test Executor` connection timeouts were a symptom of the retired low-RAM server; on the Mac they indicate an actual failure — check the test report instead of re-running with throttles.
- Check installed SDK packages with `~/Library/Android/sdk/cmdline-tools/latest/bin/sdkmanager --list_installed` (set `JAVA_HOME` first).
